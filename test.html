CASE STUDY 01

Real Estate Intelligence Platform

PropTech Startup • Seed Stage

The Decision Point

How to architect data processing for thousands of property listings

INITIAL APPROACH

Real-time scraping + GPT-4 analysis on every user query

$0.30 per analysis × 200 daily queries = $1,800/month just in API costs
OPTIMIZED PATH

Scheduled batch processing + structured queries with targeted LLM use

Pre-computed data + on-demand refinement

The Impact

~50%
Lower API costs
<2s
Query response time
Scale
Ready for 10x traffic

The Lesson

Real-time AI feels intuitive but kills your unit economics. Match processing to actual data freshness needs.

  • → Property data changes daily, not per-query—batch accordingly
  • → Reserve LLMs for summarization and recommendations, not data extraction
  • → Design for scale from day one—100 queries and 10,000 queries need different approaches
CASE STUDY 02

Healthcare Operations Platform

HealthTech • Pre-Series A

The Decision Point

When to design for compliance vs retrofitting security and access controls

COMMON APPROACH

Build MVP fast on standard infrastructure, add compliance layer before first healthcare client

Leads to: architecture rewrites, delayed launches, compliance gaps
STRATEGIC PATH

Compliant infrastructure from sprint one using managed healthcare cloud services

Result: audit-ready from day one, no rebuild needed

The Impact

6-8 weeks
Avoided rebuild delay
Zero
Compliance risks
Day 1
Enterprise-ready
ARCHITECTURE FOUNDATION
Data encryption: At rest + in transit (day one)
Access controls: Role-based from first feature
Audit logging: Built into data layer
Cloud services: HIPAA-compliant managed services

The Lesson

Regulatory requirements shape architecture, not the other way around. Retrofitting costs 3-5x more.

  • → Use managed compliant services—don't build encryption infrastructure yourself
  • → Audit requirements inform your data model from the start
  • → Enterprise buyers ask about compliance on the first call—have an answer ready
CASE STUDY 03

Intelligent Matching Platform

Marketplace Tech • Seed Stage

The Decision Point

How to architect AI-powered matching for thousands of daily queries

INTUITIVE APPROACH

Generate embeddings and run vector similarity on every user request

Works great for demos, fails at scale: 2-3s response times, rising costs
SCALABLE PATH

Pre-computed embeddings with on-demand filtering and lightweight ranking

Sub-second responses, predictable costs at any volume

The Impact

~35%
Lower infrastructure costs
<800ms
P95 response time
Linear
Cost scaling
PROCESSING STRATEGY
Profile embedding (compute-heavy) Batch process overnight
Runs once per profile update, not per query
Match filtering (lightweight) Real-time on request
Quick lookups against pre-computed data

The Lesson

Not every AI feature needs real-time computation. Understand what changes frequently vs what doesn't.

  • → User profiles update occasionally—compute embeddings then, not on every search
  • → Keep query-time logic simple and fast—filter, don't recompute
  • → Users care about fast results, not whether the AI ran 60 seconds ago or right now

The Pattern: Early Technical Choices Compound

These weren't about building more features. They were about building the right foundation.

Common Mistakes We See

  • × Choosing models based on demos, not production constraints
  • × Treating compliance as a deployment problem, not an architecture decision
  • × Optimizing for development speed instead of operational efficiency
  • × Assuming "AI" means everything must happen in real-time
  • × Building custom solutions for problems cloud services already solve

What Actually Works

  • ✓ Match technical complexity to actual problem requirements
  • ✓ Design for constraints (cost, compliance, latency) from day one
  • ✓ Validate assumptions with small technical proofs before full builds
  • ✓ Pre-compute when possible, process on-demand when necessary
  • ✓ Use managed services—build competitive advantage, not infrastructure

What This Means For Your MVP

Before you write code, answer:

1. What's the simplest model that solves 80% of the problem?
Start with structured data and basic ML. Add LLMs only where text understanding creates value.
2. What constraints must shape the architecture?
Compliance, latency requirements, and cost limits aren't post-launch problems.
3. Where does real-time processing actually create user value?
Most AI products don't need instant inference. Pre-compute when you can.
